# Прогноз повторной покупки

Первый учебный ML-проект: предсказать, совершит ли покупатель оплаченный заказ в следующие 30 дней. Все транзакции синтетические; результат демонстрирует процесс обучения и оценки модели, а не прогноз для реального магазина.

## Постановка

Одна строка — один клиент на дату прогноза. В анализ входят только клиенты с оплаченной покупкой за предыдущие 90 дней. Для каждого клиента используется одна дата прогноза: 1 мая, 1 июня, 1 июля или 1 августа 2026 года. Клиенты обучения и теста различаются.

Признаки:

- `recency_days`: дни с последнего оплаченного заказа.
- `orders_90d`: число оплаченных заказов за прошлые 90 дней.
- `spend_90d_rub`: сумма покупок за прошлые 90 дней.

Признаки используют окно `[дата прогноза - 90 дней, дата прогноза)`. Цель `returned_30d` равна 1 при наличии оплаченного заказа в окне `[дата прогноза, дата прогноза + 30 дней)`. Неполные окна будущего исключаются. Идентификатор, даты и целевая переменная не передаются модели как признаки.

## Модель и проверка

Логистическая регрессия в Pipeline со StandardScaler. Среднее и масштаб признаков оцениваются только на обучающих данных. Baseline — константная вероятность возвращения, равная доле возвращений в обучении.

Май и июнь используются для обучения, июль и август — для теста. Все обучающие ответы уже известны к первой тестовой дате. Порог 0,5 выбран заранее. Гиперпараметры и порог по тестовой выборке не подбираются. При добавлении подбора параметров нужна отдельная временная валидация.

Метрики: ROC-AUC, average precision, Brier score, accuracy, precision, recall, F1 и матрица ошибок. [Фактические результаты](results/RESULTS.md).

## Запуск

Python 3.12:

```sh
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements-lock.txt
python generate_data.py
python train.py
python -m unittest discover -s tests -v
```

На этом компьютере окружение уже установлено. Достаточно активировать `.venv` и выполнить последние три команды. Генератор с фиксированным seed перезаписывает два CSV в `data/`; обучение перезаписывает результаты в `results/`. Если хотите обучиться на поставляемых данных без пересоздания, пропустите `generate_data.py`.

```text
results/coefficients.csv     # коэффициенты стандартизованных признаков
results/RESULTS.md           # итог эксперимента
```

## Ограничения

Синтетический генератор задаёт клиентам разные скрытые склонности к покупкам. Эти склонности не передаются модели, но создают зависимость между прошлым и будущим поведением. На реальных данных связь может быть другой. Сумма покупок коррелирует с частотой; коэффициенты нельзя интерпретировать как причинное влияние.

Один временной тест не заменяет проверку устойчивости по нескольким периодам. Не проводились подбор порога, оценка доверительных интервалов, отдельная проверка калибровки или внедрение. Сам прогноз покупки не оценивает влияние скидки или рассылки.
